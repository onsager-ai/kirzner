# Founder experience evidence

The start form accepts product, current objective, and resource constraints. Other brief fields remain explicitly unknown until the founder adds them. The latest research task stays on Opportunities for copy and return paste, and older tasks remain reachable through Handoffs. A research return can carry both a source-grounded opportunity and a bounded experiment draft; importing that return creates neither an experiment nor an approval. The founder chooses whether to use the draft, edits its prefilled content, and approves a specific version separately.

The primary experiment workspace connects the source opportunity, current proposal, decision, task handoffs, returned materials, reviews, actions, observations, and next decision. It surfaces the current blocker and next action. Preparation and review remain founder decisions; external agents retain their own execution, credentials, retries, and scheduling. The baseline listed all experiment cards and required separate Handoffs and Results views to reconstruct progress; it had no saved experiment selection or connected progress summary. Reopening a direct experiment URL now requires no additional view change and is checked for both the same selected experiment and its current next step. The home page also offers a single Resume current experiment link; the browser verifies that click separately from the primary navigation count.

The original browser journey is a source-derived baseline, not a user study: it fills eight required business-brief values, reconstructs all nine proposal fields manually, visits five separate top-level views, and makes six top-level navigation changes through its first action, observation, and next decision. Its full script adds two navigation changes and two JSON file imports for revision/conflict regressions. It contains no timer, so it gives no human elapsed-time baseline. The existing file-based handoff path requires two task exports and two return imports plus a material upload; the old browser primary flow instead used manual return forms. These are labeled source-derived paths, not measured external-agent transfers.

The primary synthetic journey writes `frontend/test-results/founder-friction.json` when run through npm, with measured counts for three required brief fields entered, no proposal fields reconstructed, one prefilled field edited, two task-brief clipboard copies, two pasted task returns, one local deliverable upload, no primary-flow file imports or downloads, and two top-level route changes. The copy/paste steps remain part of the external-agent workflow; the browser fixture does not run an agent. Intentional malformed, mismatched, duplicate, and conflicting return retries are reported separately and excluded from primary transfer counts. Additional regression navigation runs after the primary counts are frozen. The artifact records no human timing or savings. The CI evidence set also includes primary-stage and final regression screenshots at 1280px and 390px in light and dark themes, the browser trace, bounded application-log tails, and `test-results/worked-example.json`.

The browser fixtures use synthetic opportunity/return data and clearly labeled synthetic action, observation, and decision records. They verify version approval, duplicate/conflicting returns, malformed and mismatched paste handling, reset of unsent paste text/errors when a new research task replaces the inline task card, access to the older task by ID, unknown-effect reconciliation without retries, accepted materials from partial and failed execution reports, preservation of accepted material while a later task is pending, historical action timestamps at whole-second precision, an additional observation on the same action, experiment switching with colliding local action/observation IDs, distinct zero-opportunity research statuses, file compatibility, original acceptance criteria, selection after reopening, and mobile overflow. They also check that an approved self-prepared action advances to observation without an agent handoff. These checks establish software behavior only; they do not establish real agent execution, customer pain, reachable participants, demand, or business success.

The worked example uses real pinned public Semon documentation as technical source material. Its opportunity/draft planning data and task-return wrapper are labeled synthetic, and no Semon session or external agent execution is claimed. It ends after source-material review with zero actions, observations, and adopted learning. No prospect contact, publication, purchase, deployment, or private-log inspection occurs.
